### #8 decision-inbox.js:160 POST / — CONFIRMED but impact overstated on "phishing link"; core defect stands, P2 reasonable
Read decision-inbox.js in full (190 lines). `r.post('/', ...)` (line 160) has zero auth/permission gate, accepts caller-supplied `urgency` (validated only against `{high,medium,low}` — 'high' passes trivially), arbitrary `title`/`rationale`/`link`, and calls `publishRecommendation` which upserts directly into `decision_recommendations` with only structural validation (dedupKey/sport/type/title/sourceModel presence — no auth check, no rate limit). Confirmed Home.tsx:30 fetches `/decision-inbox` unauthenticated-client-side and Home.tsx:92 renders `rec.link` via **react-router's `<Link to={rec.link}>`** (Home.tsx:2 `import { Link } from 'react-router-dom'`). This is a materially important correction: react-router v6's `Link`/`useHref` does NOT special-case absolute external URLs — passing `"https://evil.example"` as `to` does not produce a real cross-origin navigation; it gets resolved as a relative path against the current route and produces a broken internal SPA link (at worst a 404 inside the app), not an actual redirect to an attacker's phishing site. So "a phishing link into Nick's fantasy decision queue" that a user would actually be redirected to is not accurate as literally described — clicking it would not leave the app. That said, the underlying defect is real and still meets the impact bar on its own terms: an unauthenticated tunnel caller can inject a fabricated, arbitrarily-titled "high" urgency item with fake rationale/expected-value directly into the queue Nick reads at the top of his Home dashboard as if it were a real model-generated recommendation (sourceModel is also caller-controlled, so it can impersonate `trade-engine`/`waiver-brain`). That is a genuine "decision recorded" risk — Nick could act on fabricated fantasy advice believing it came from his own engines. Verdict: not refuted, but corrected_claim should drop "phishing link" framing (the link itself is inert for external redirection) and keep the "fabricated recommendation impersonating a real engine" framing. P2 is fair, not clearly overstated once the link/redirect claim is corrected.
