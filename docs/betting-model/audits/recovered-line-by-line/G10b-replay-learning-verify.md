## #86 nfl-props-replay.js:44 — half-point rounding bias
- Line 44 exact match: `const toHalfPoint = v => Math.round(v * 2) / 2 + (Number.isInteger(Math.round(v * 2) / 2) ? 0.5 : 0);`.
- Verified arithmetic: v=50.0 → round(100)/2=50 (integer) → +0.5 → 50.5. v=49.5 → round(99)/2=49.5 (not integer) → +0 → 49.5. The function only ever *adds* 0.5 when the naive half-point rounding lands on a whole number; it never subtracts. Since (for continuously-distributed inputs) roughly half of all values round to an integer under nearest-half rounding and half already land on X.5, the added 0.5 fires on (on average) half of all cases, producing an average upward shift of 0.5 * 0.5 = 0.25 versus a symmetric half-point rounding rule — matching the claim's "+0.25 on average."
- A systematically-higher line makes the player's actual stat less likely to exceed it, i.e. favors "Under" — consistent with the claim.
- `nfl-props-replay.js:182`: `if (act === b.line) { push++; ...}` — since `line` is always a half-point value (X.5, never a whole integer, by construction of `toHalfPoint`) and `actual` player stats (yards, receptions) are integers, `act === b.line` can never be true regardless of the +0.25 bias — pushes are structurally impossible for ANY half-point line, not specifically because of the upward-only bias. The claim's "Pushes ... therefore never occur" is true as stated but its causal framing ("therefore," implying the bias causes the push-avoidance) slightly overstates the connection — half-point lines avoid pushes by design regardless of which direction the rounding bias runs. This doesn't undermine the core defect (the bias itself, and the Under-favoring skew), just a minor imprecision in a supporting evidence sentence.
- CONFIRMED, high confidence on the core claim (systematic upward bias, Under-favoring); minor overreach flagged in the "therefore pushes" aside.
