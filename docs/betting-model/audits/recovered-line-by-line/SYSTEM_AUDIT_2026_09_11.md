## A. Verdict in ten sentences

1. The **structure is good where it matters least and messy where it matters most**: the boot/platform/DB/migration spine (G01, G02), the fantasy player-model core (G13b), the draft/trade layer (G13a), and the audit/replay machinery (G10a) are all rated *acceptable* — careful, walk-forward, honestly documented — while the market-data layer (G09), the execution/money path (G08), the client betting surface (G16), and the props pipeline (G11, rated *broken*) are rated *messy* or worse.
2. The **wiring is mostly right but has real, checkable holes**: 13+ route families sit unauthenticated behind the phone tunnel (`server/index.js:76-107`), a boot-time seed function silently reverts AI team analyses, user edits, and the draft board every restart (`server/db/seed/index.js:27`), and two one-line producer omissions (`book-feeds.js:417`, `nfl-prop-clv.js:98`) each break an entire measurement pipeline (the T-60 prospective experiment; all prop-model CLV) end to end.
3. **The money path is not actively bleeding cash today, and is not fully safe either.** No code path currently sizes a persisted stake from a model probability — every real stake is human-entered or gated at zero (`nfl-execution-edge.js:625`) — but an unauthenticated route can fabricate a "placed" teaser settlement from caller-supplied scores (`nfl-teaser-execution.js:307`), a client-side "reachable" checkbox that gates the only claimed +EV bet is hardcoded `true` with no verification (`ProfitabilityControl.tsx:105`), and the shopping board the one positive edge depends on structurally drops the book that anchors that edge (`nfl-shopping-board.js:92`).
4. **The fantasy path is functionally complete but has one dead loop and one silent-loss loop**: the weekly forward-evidence capture for fantasy has *never* produced a single snapshot and is now permanently blocked for the season (`weekly-learning.js:69`), and `seedIfEmpty` (item 2 above) is the single highest-priority fantasy-side fix because it is *currently, silently* erasing the draft board and team intel on every restart.
5. **Betting has a settled, honest, negative headline** (no edge vs the close; the only positive is execution/line-shopping and the Wong 2-team-6-point teaser), and the codebase mostly respects that — nothing auto-promotes a betting model to production, stake authority is gated shut — but 58 commits of real work (including the session that closed the worst of these holes) sit unpushed on one laptop with no off-machine copy, one GitHub OAuth-scope error away from staying that way indefinitely.
6. **Nothing here should be read as "the models secretly work" or "the models are secretly broken"** — the modelling discipline (cutoff safety, walk-forward, preregistration) is unusually good across the fantasy, MLB, and Python research code; the defects found are almost all in the *wiring around* good models (auth, sync gaps, mislabeled UI, stale docs), not in the statistics themselves.
7. **Data organization is sound in schema, risky in operations**: 262 tables, migrations 000–035 all apply cleanly and are covered by tests, but the daily integrity check now takes 168 seconds and every migration snapshot needs 11+ GB of free disk that is not being pruned, the WAL file has grown 3.6× unchecked, and there is no retention policy anywhere for the market-quote tables that write ~1.3M rows/hour during a live capture window.
8. **Documentation is unusually honest in its own self-corrections and unusually stale in its status registers**: `docs/CLAUDE-NEXT-STEPS.md` — the one document both Nick and Codex are meant to treat as canonical — is missing its own most safety-critical session's findings, and the root README and governance manual both still headline a superseded audit run (Run 7, `-11.77%` ROI) when three later runs (27/31/32) exist and are canonical in the plan itself.
9. **What to do now, in one sentence**: fix the seed-on-boot data loss and the two one-line evidence-pipeline gaps first (all three are P1, all three are one-line fixes with a clear test), close the unauthenticated-route list before the tunnel is used again, then continue exactly the fantasy-first priority Nick has already set — the betting engine has nothing time-critical waiting on it except governance hygiene.
10. This report's job is to make all of that checkable, not to re-argue it: every defect below cites the file and line a person can open right now, and every "do this" in Section I names the exact file and the exact test that proves it's done.

### B.2 Wiring problems found on this map (see Section D for full citations)

- **Seed reconcile writes into the fantasy decision layer on every boot** (`server/db/seed/index.js:27`, called unconditionally from `server/index.js:58`) — this is a live edge from PLATFORM back into FANTASY LEDGERS that the diagram above doesn't show because it shouldn't exist: a boot-time job is overwriting draft-board ranks and team analyses that only the decision layer should touch.
- **The evidence pipeline into the T-60 packet is starved by a one-line omission**: `book-feeds.js:417` and `line-shopping.js:66` never pass `receivedAt`, so the "prospective decision at cutoff" arrow from TABLES into the BETTING DECISION LAYER's decision tape can never carry a real receipt-clock quote — the whole point of the T-60 architecture is structurally unreachable until this is fixed.
- **The props arrow is severed at the join key**: `projections.js` names players by nflverse abbreviation (`D.Maye`) since commit `129115e`, while `nfl-prop-clv.js:98`, `nfl-props.js`, and `td-regression.js:310` all key by full sportsbook name — zero prop quotes have matched a projection since 2026-08-31, and settlement is independently and permanently broken by the same mismatch (`nfl-prop-clv.js:429`).
- **The MLB decision layer runs but the arrow into MLB LEDGERS is closed**: `priceForwardCandidates` gates on `odds_status==='captured'`, and MLB odds capture has been off since 2026-09-01 (credit-drain guard, `mlb-pregame.js:41`), so `mlb-auto-picks.js:193` recomputes a full board every 90 minutes and discards it — 104+ scheduler runs, zero picks, real cost.
- **The betting evidence-firewall arrow reads the wrong ledger's close**: `nfl-evidence.js`'s `validationFirewall` counts `shadow_decisions` toward the forward-sample target, but `shadow-ledger.js:71` grades CLV against the live, unfrozen `game_lines.spread/total` (which `syncCurrentLines` can overwrite post-kickoff) instead of `closing_spread/closing_total` the way `forward-ledger.js:149` correctly does — the ledger the system treats as its cleanest forward evidence is not frozen the way its sibling is.
- **Auth is a patchwork, not a boundary**: five-plus-`dev` route families get `legacyAuthenticated` at mount time (`server/index.js:78,88,91,97,98`); everything else (teams, rankings, espn, aggregates, analysis, nfl, stats, accolades, edge, props, props-tickets, decision-inbox, wong, and both `/api/execution-slate/*` routes) is either self-gated inconsistently or fully open. The loopback bind (`127.0.0.1:5177`) makes this moot on the laptop; the moment `scripts/tunnel.mjs` is up for phone access (a real, documented, recurring workflow — see memory `gridiron-phone-access`), it is not moot.

## D. Confirmed defects

Severity key: **P1** = wrong money / wrong decision / data-integrity break / leakage / security. **P2** = wrong number or misleading output, bounded blast radius. **P3** = hygiene, called out only where materially interesting.

### D.1 — P1 defects (full detail)

#### Money path, authorization, and ledger integrity

1. **`server/db/seed/index.js:27`** (called unconditionally from `server/index.js:58`) — `seedIfEmpty` is misnamed: it runs on *every* boot and `ON CONFLICT ... DO UPDATE`s static July editorial text and default draft-board ranks over whatever is currently in `nfl_teams`/`ranking_entries`. **Impact**: overwrites AI-generated team analyses (`routes/analysis.js:81`), user team edits (`routes/teams.js:108`), ESPN head-coach sync (`routes/nfldata.js:97`), and the user's own draft-board ordering (`routes/rankings.js:19,53`) on every single restart; confirmed live — `nfl_teams.analysis_updated_at` timestamps within the last day sit next to text that will revert on the next boot. **Fix**: `INSERT OR IGNORE` for teams, create-if-absent for the ranking set, never `DO UPDATE` editorial/rank columns; or gate behind an explicit `--reseed` flag. **Exit test**: restart the server twice, assert a manually-edited team analysis and a manually-reordered board rank both survive both restarts.

2. **`server/index.js:76-107`** — 13 route families (teams, rankings, espn, aggregates, analysis, nfldata, stats, accolades, edge, props, props-tickets, decision-inbox, wong) mount with no auth of any kind, including `/api/analysis` (paid Claude calls) and `/api/edge/scout/:id` (`edge.js:259`, paid Claude call, no gate at all) and `/api/betting/explain/page` (`betting-hub.js:878`, paid, checks only that an API key string exists). **Impact**: while `scripts/tunnel.mjs`'s Cloudflare quick tunnel is up (a real, documented, recurring phone-access workflow) anyone with the URL can spend the Anthropic budget, wipe ESPN cookies (`espn-connect.js:249`), or rewrite team analyses and rankings. **Fix**: global middleware requiring a session for any request carrying forwarding headers, or move these mounts under `legacyAuthenticated`. **Exit test**: with the tunnel up, an unauthenticated `curl` to each of the 13 mounts returns 401.

3. **`server/services/nfl-teaser-execution.js:307-360`**, reached via `betting-hub.js:450` and `wong.js:629` (both unauthenticated, both mounted without `legacyAuthenticated` per `server/index.js:107-108`) — `settleTeaserExecution` grades legs from caller-supplied `input.scores` with **no lookup against `game_lines`**, then `UPDATE`s a mutable (`nfl_teaser_executions`/`_legs`) ledger. **Impact**: the forward P&L record of the one strategy the project believes is +EV can be set to any value by any client that can reach the API, with no trace (rows are mutable, not append-only). **Fix**: grade from `game_lines` by event/team/opponent (as `settleExecutionOpportunities` already does correctly), refuse settlement until scores are final, add `requireModelPermission('model:execute')` to both settle routes. **Exit test**: a settle POST with a fabricated score for a game not yet final is rejected; a settle POST is rejected without a valid session.

4. **`client/src/components/betting/ProfitabilityControl.tsx:105`** and **`Edges.tsx:102`** — both hardcode `reachable: true` in the POST body that records a Wong teaser price; server (`nfl-profitability.js:78,86,90`) trusts this flag verbatim and it is the sole discriminator for `wong_price_gate_passed`. **Impact**: the go/no-go gate on the only measured +EV bet on the desk is a free-text book-name field plus a price pre-filled at exactly the passing boundary (`-115`), with zero verification anywhere in the chain. **Fix**: make `reachable` a real checkbox defaulting to `false`; remove the `-115` prefill; stop asserting "Manually verified" in the stored note. **Exit test**: saving a price with `reachable` unchecked stores `reachable=0` and does not flip `wong_price_gate_passed`.

5. **`client/src/components/draft/SourcePill.tsx:42`** — calls `/drafts/:id/capture-bookmarklet` with no `ingest_key` query param; the server (`draft-capture.js:40-43,60-63`) always 400s without one, and no client code ever calls `POST /drafts/:id/ingest-key` to mint one. **Impact**: the entire ESPN-tab WebSocket capture path — the low-latency draft mirror Nick's own memory records as his preferred draft-night setup — is unreachable from the UI; the board still works via a 4-second server-side poll, so this is not silent, but the faster path cannot be turned on. **Fix**: have `SourcePill` first `POST /drafts/:id/ingest-key`, then request the bookmarklet with `?ingest_key=...`. **Exit test**: clicking "Get the ESPN tab bookmarklet" on Live Draft produces a working bookmarklet, not "ingest_key required."

#### Evidence-pipeline integrity (the T-60 experiment, audits, props)

## F. Data organization

**Verdict: the schema is careful; the operations around it are not yet trustworthy.**

- **Size and shape**: 262 tables, 340 indexes, 169 triggers, 25.25M rows, 11.7 GB table data + indexes = matches the on-disk file size. Growth is not uniform: `polymarket_quotes` alone writes ~1.27M rows/hour during a live capture window (13.5M rows total, 0.4% carrying a real order book); `nfl_line_snapshots` ~300K/day; `nfl_blind_input_mutations` (an audit journal, not a data table) +250-680K rows/day.
- **Retention**: **there is no retention or archival policy anywhere in this codebase** for any market/quote-tape table. This was independently flagged by a prior session (before this audit) and again in this audit; nothing has changed between the two observations except the numbers getting larger.
- **Backup**: `backupBeforeMigration` is well-designed (a real `VACUUM INTO` snapshot, not a raw file copy, specifically because WAL-mode pages can be missed) and deliberately never auto-prunes — "deleting a recovery point is a judgment call that belongs to a person who knows what's in it" is the code's own stated policy, and this audit agrees with it. The problem is the guard's *cost*, not its design: every pending migration now needs `dbSize + 2GB` free (≈13.7 GB today), and at current growth roughly five more migrations exhaust the ~66-73 GB currently free before the guard's own refuse-to-boot fires — on a game day, that is an outage.
- **WAL**: 3.35 GB, up 3.6× from a previously-flagged 932 MB, because nothing in the codebase ever issues `PRAGMA wal_checkpoint(TRUNCATE)`. Default PASSIVE auto-checkpointing folds committed pages back but never shrinks the file on disk. Not currently blocking anything (66+ GB free), but it eats into the same headroom the migration guard depends on and is not counted by that guard's own math (which only sizes the main `.sqlite` file).
- **Daily integrity check**: `PRAGMA quick_check` now takes 168 seconds on the 11.2 GB file, runs synchronously at import before migrations/routers/the T-60 runner load, and is throttled to once per 24 hours — the throttle is correct, the position on the boot path is not.
- **Tables no code reads**: `auction_sales`, `auction_settings` (fully dead, see D.3), `nfl_scottfree_game_features` (has an import script and a test, no serving path — a judgment call for Nick, not a delete), `model_actor_provenance_quarantine` (migration-scoped, test-only, correctly so). 58 of 261 tables have zero rows; the overwhelming majority of those are legitimate unexercised scaffolding (the entire `nfl-execution` domain — 27 tables, 1,004 total rows — is built and essentially idle, consistent with "fantasy over betting, betting engine is secondary").
- **Tracked runtime artifact**: `server/data.sqlite.pre-migration-2026-09-11T00-19-06-457Z.bak-journal` (1 KB) is currently committed to git — a page-image fragment of a database that legitimately holds ESPN session cookies, and it ships in every release zip built via `git ls-files`. The `.gitignore` gap that let it in has already been patched twice for other filename shapes; this is the third gap in the same pattern.
- **A live, previously-known-but-recurring data-quality defect**: `nfl_qbr_weekly` season=2026 is 99.3% (537/541) exact copies of season=2025, written 2026-09-10 in one batch, unflagged. A prior session flagged this and judged it "doesn't leak into Week 1" — this audit found that assessment was already slightly too optimistic before it was even written (the placeholder covers Week 1 too, since real 2026 CSV data hadn't landed), though every actual production consumer traced in this audit is cutoff-safe by construction and currently reads only real season≤2025 data. It becomes live risk the first time the weekly `syncQbr()` resync stalls between now and a week-2 build.
