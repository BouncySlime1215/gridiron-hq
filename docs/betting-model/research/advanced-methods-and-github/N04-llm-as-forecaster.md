# N04 — LLMs as direct numerical forecasters (not news extractors)

Bucket: **new** (agent-level). Candidates below are 3 fix / 3 new to hit the 50/50 grounding requirement.

## Primary sources read in full

### 1. Halawi, Zhang, Yueh-Han, Steinhardt (2024) — "Approaching Human-Level Forecasting with Language Models"
arXiv:2402.18563, UC Berkeley. Read in full (10 pp + appendix skim).

- **System**: retrieval (LM-generated search queries -> NewsCatcher/Google News -> LM relevance filter -> LM summarization) feeding a reasoning LM (GPT-4-1106-Preview, optimized scratchpad prompt) plus a self-supervised fine-tuned GPT-4-0613, ensembled by **trimmed mean** of 6 forecasts (3 base + 3 fine-tuned).
- **Data**: 5,516 curated binary questions from 5 platforms (Metaculus, GJOpen, INFER, Polymarket, Manifold); **3,762 train / 840 val / 914 test**. Test set restricted to questions opened after the models' knowledge cutoff (June 1 2023) to prevent leakage.
- **Baseline**: raw pretrained LMs score ~0.22–0.25 Brier (barely beats 0.25 random); best baseline GPT-4-1106-Preview = 0.208 vs. human crowd 0.149.
- **Main result**: optimized system Brier **0.179** vs. crowd **0.149** (gap 0.03); accuracy 71.5% vs 77.0%. System is well-calibrated (RMS calibration error 0.42 vs crowd 0.38) despite base models being poorly calibrated zero-shot.
- **Where it wins**: crowd-uncertain questions (system 0.199 vs crowd's 0.246 Brier when crowd is 0.3–0.7); early retrieval dates; when 5+ articles retrieved. In a "selective" mode restricted to these conditions, system Brier (.175) beats crowd (.142) is still worse — but accuracy leg with all 3 criteria jointly (58.0 vs 54.2) beats crowd on that subset.
- **Where it loses**: questions where the crowd is highly confident (system under-outputs extreme probabilities — safety-training hedging).
- **Limitation stated by authors**: system "nears" but does not clearly beat the aggregate crowd on the full test set; degrades relative to crowd at later retrieval dates (crowd catches up as more information becomes public).

### 2. Schoenegger, Tuminauskaite, Park, Tetlock (2024) — "Wisdom of the Silicon Crowd: LLM Ensemble Prediction Capabilities Rival Human Crowd Accuracy"
arXiv:2402.19379v6. Read in full (16 pp).

- **Study 1**: crowd of **12 diverse LLMs** (GPT-4, GPT-4+Bing, Claude 2, GPT-3.5-Turbo-Instruct, Solar-0-70B, Llama-2-70B, PaLM2, Coral/Command, Mistral-7B-Instruct, Bard/PaLM2, Falcon-180B, Qwen-7B-Chat), each queried 3x per question via each vendor's own chat UI (not API — held prompt constant, not temperature), median-aggregated, on **31 binary questions** from a live 3-month (Oct 2023–Jan 2024) Metaculus tournament with **925 human forecasters**.
- **Preregistered result**: LLM crowd Brier **M=0.20 (SD=0.12)** significantly beats the 0.25 no-info baseline, t(30)=-2.35, p=.026. LLM crowd vs. human crowd (M=0.19): **not statistically different**, t(60)=0.19, p=.850 — and a non-preregistered equivalence test (Cohen's d=0.5 bounds) supports practical equivalence, "though the bounds are quite wide."
- Only **3 of 12** individual models beat the crowd median (consistent with standard wisdom-of-crowds theory — aggregation, not any one model, is doing the work).
- **Acquiescence bias**: mean LLM forecast M=57.35 (SD=20.93), significantly above 50 (t(1006)=86.20, p<.001) even though only ~45% of questions actually resolved Yes — LLMs skew toward "yes"/round numbers regardless of true base rate.
- **Calibration**: most individual models overconfident (Calibration Index up to 0.212 for Coral/Command); the aggregate itself is *better* calibrated (CI 0.041) than the median individual model — calibration comes from aggregation, not from any single model being calibrated.
- **Study 2** (GPT-4, Claude 2, within-model pre/post): showing the model the human crowd median **significantly improves** its own Brier score (GPT-4: 0.17→0.14, p=.003; Claude 2: 0.22→0.15, p<.001) and narrows its prediction interval — but the updated LLM forecast is still **significantly worse** than simply averaging the LLM's initial forecast with the human median (paired t-tests, p=.011 and p=.001) — i.e., naive human-in-the-loop updating underperforms a dumb average.
- **Honest limitation**: crowd size (12) is small versus the theoretical wisdom-of-crowds literature; equivalence bounds are wide; models were queried through consumer chat UIs, not controlled APIs, so exact prompting/sampling is not fully reproducible.

### 3. Paleka, Goel, Geiping, Tramèr (2025) — "Pitfalls in Evaluating Language Model Forecasters"
arXiv:2506.00723 (ETH Zürich / ELLIS / MPI Tübingen). Read in full (10 pp). This is the load-bearing "honest critique" source.

- **Challenge 1 — trusting evaluation results (temporal leakage)**:
  - *Logical leakage in backtesting*: selecting "future-resolving" questions from a past vantage point can itself leak the answer (their Queen-Elizabeth-age example). Empirically, they find **≥3.8% of Halawi et al.'s own test set** consists of questions that could not have resolved otherwise (e.g., "Will Sudan experience civil war before 2036?" collected in a window where only one resolution was logically live), and **≥10%** of a comparable dataset (Tao et al. 2025) is similarly trivial.
  - *Unreliable date-restricted retrieval*: search engines' date filters are unreliable (demonstrated concretely: a "jan 6" query restricted to pre-2020 surfaces results only interesting because of the Jan 6, 2021 insurrection; a "wuhan" query restricted to pre-Dec-2018 prominently surfaces the Wuhan Institute of Virology, salient only after COVID).
  - *Over-reliance on stated knowledge cutoffs*: empirically shown to leak — GPT-4o (stated cutoff Oct 2023) correctly reports a Nov 15, 2023 Biden-Xi meeting when jailbroken, despite denying knowledge of it under normal prompting.
- **Challenge 2 — extrapolating benchmark performance to real skill**:
  - *Piggybacking on human forecasts*: many "LLM matches human crowd" claims are circular if the model's retrieval system can see the very market/crowd prediction it's being compared against (a live risk for ForecastBench-style evaluations).
  - *Gaming benchmarks through betting*: on correlated question sets (e.g., many 2025 questions all conditioned on who wins the 2024 election), a forecaster maximizing benchmark rank should bet confidently on the correlated latent variable rather than report honest calibrated probabilities — a real 2022 human forecasting-contest winner admitted exactly this strategy.
  - *Skewed data distributions*: forecasting benchmarks (they audit ForecastBench's 6,402-question breakdown) are dominated by a few sources (ACLED conflict data, crypto/sports-heavy Polymarket, personal Manifold questions) — performance may not generalize.
  - *Imperfect metrics*: accuracy is not a proper scoring rule; Brier score confounds calibration and base-rate skill (their worked example: a forecaster with real skill on rare events but base-rate-only on coin-flip events can score *worse* in aggregate Brier than a forecaster with zero skill on rare events but slightly better calibration on coin flips).
- **Recommendation**: restrict retrieval to date-verifiable corpora (or TF-IDF/older embeddings), validate every question resolves both ways were logically possible, report Brier+log-score+calibration together, and — critically — preregister trials and evaluate on genuinely prospective (not backtested) questions wherever possible.

### 4. Hsieh, Fu, Chen (2024) — "Reasoning and Tools for Human-Level Forecasting" (RTF)
arXiv:2408.12036, UC Berkeley, NeurIPS 2024 workshop. Read in full (8 pp).

- **System**: hierarchical ReAct agents — a high-level GPT-4o planner that calls low-level ReAct agents equipped with Google Search API and a **Python interpreter for numerical simulation** (not just text retrieval). This tool-use (code execution) angle is the piece Halawi's system lacks.
- **Data**: 201 questions scraped from Manifold Markets on April 15, 2024, filtered to yes/no-answerable and resolving April 16–May 15, 2024 (strictly after retrieval cutoff, avoiding the Halawi-style near-miss leakage flagged by Paleka et al.).
- **Result**: RTF median-of-3 Brier **0.169** vs. crowd **0.172** (essentially tied, RTF nominally better here on a smaller/easier sample) vs. accuracy 72.4% RTF / 73.8% crowd; base GPT-4o alone scores 0.265 (worse than 0.25 random guessing). RTF's calibration index (0.0129) is much better than raw GPT-4o (0.0194) and only slightly worse than the crowd (0.0101).
- **Key mechanistic finding**: hierarchical planning (a reasoning agent orchestrating tool-calling sub-agents) matters — a flat single ReAct agent exhausted its context/timed out on complex multi-tool queries; splitting reasoning from execution fixed this.
- **Authors' own stated limitation**: "the evaluation dataset is based on prediction market data and popular questions rather than domain-specific questions" and the Google Search tool "lacks nuanced, context-specific understanding" — i.e., they do not claim this generalizes to a specialized numeric domain like football stat lines without validation.

### 5. Recall (recallnet), "NFL Arena" live-prediction analysis (Sept 2026) — read as a snippet only, NOT read in full
X/recall.net post + linked article (`x.com/recallnet/status/1996286117868343414`, article id 1996223919141916953). **Not a peer-reviewed source** — a vendor marketing/blog post, included because it is the most concrete *sports-specific* failure evidence found and matches tonight's own audit findings almost exactly.
- Claim: 6 frontier LLMs (GPT, Claude, Gemini, Grok, DeepSeek family — exact roster not independently verified by us), 1,500+ predictions, **3 live NFL games**. Every pregame favorite pick (Chiefs, Ravens, Lions) lost. In-game, models "mostly parroted Vegas odds," and several models (DeepSeek, Grok on a Cowboys game; Gemini/GPT-5.1/Grok on a Bengals game) **never flipped their pick even as the trailing team built a double-digit 4th-quarter lead** — the most confident models were the most wrong.
- Why it's cited despite being unverified: it is the single sports-domain analogue of exactly the shrinkage-to-market and overconfidence-on-wrong-calls failure modes tonight's audit already found *inside Gridiron's own* nfl-ensemble.js (naive 0.632·market shrinkage) and nfl-drive-sim.js (win-probability updating bugs) — independent, if informal, replication that "ask an LLM the score live" is not a free win. Treated as a **do-not-do warning**, not as evidence to build on. n=3 games is far too small to generalize from and we flag that explicitly.

## Repos

### Metaculus/forecasting-tools
- MIT license, 78 stars, **last commit 2026-09-09** (3 days before this research) — actively maintained, cloned to `github/Metaculus__forecasting-tools` (27MB, no node_modules/venv).
- What it actually is (verified by reading code, not README): a Python framework (`forecasting_tools/`) with (1) `forecast_bots/forecast_bot.py` (1043 lines) — an abstract `ForecastBot` class wrapping research→reasoning→numeric/binary/multiple-choice prediction, one official template per Metaculus tournament season back to 2025; (2) `cp_benchmarking/benchmarker.py` — a `Benchmarker` class that runs N bots against a question batch and scores vs. the Metaculus community prediction, with an explicit note in its docstring: "100-200 questions is a decent starting point... even with 100 there is ~30% of the 'worse bot' winning if there are not large skill differences" (a built-in sample-size honesty check that Gridiron's own trial process currently lacks); (3) `calibration_adjustment/` — `CalibrationAdjuster` abstract base class (`train(df)`, `adjust_binary_forecast(p)`, `test(holdout_df)`) with **four concrete implementations already written**: constant-shift, logistic recalibration, decision-tree, k-means; (4) `data_models/numeric_report.py` — a `NumericDistribution`/`Percentile` schema that elicits and stores a full **CDF via percentile points** (not a point estimate), with an explicit max-PMF-value cap to prevent over-concentrated (overconfident) distributions.
- License permits porting. Adopt: **port** the `CalibrationAdjuster` interface and the `Percentile`/`NumericDistribution` schema idea (small, self-contained, no heavy deps); **reference-only** for the full `ForecastBot`/`Benchmarker` scaffolding (it's Metaculus-API-specific — the pattern is worth copying, the code is not directly attachable to Gridiron's Node/Postgres-ish stack).
