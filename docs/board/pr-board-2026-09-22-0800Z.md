## Method

Same basis as the item-6 triage: `git merge-tree --write-tree 654ff93
<head>` for conflict state (not GitHub's `mergeable_state`, which
reads `unstable` for every PR right now because CI workflow
`357164314` is disabled, not because of real conflicts — see item-6
doc, finding #2). Presence of a Five-Questions block and a tree-hash
or commit-anchored check figure in the PR body are read from the body
as posted, not re-verified line-by-line except where flagged below.

Two standards apply for the first time in this pass, from the
Opportunity thread via the coordinator:

- **Per-league wiring.** A feature counts as `wired` only if wired for
  **every** league in the platform, not just whichever one happens to
  have data. A feature that works for one league and is silently
  absent for the other four is `silently broken`, not `wired`.
- **Hand-run script never counts as wired.** A consumer with zero
  importers, absent from `package.json`, named nowhere under
  `server/`, and reachable only via `node scripts/...` by hand is the
  weakest reach category and always reads as NOT wired — weaker than
  a mounted route or a scheduled job.

Neither standard changed any call in this pass (no PR in the 45 both
claims wiring and fails one of these two tests), but both are now
part of how future triage reads a wiring claim.
