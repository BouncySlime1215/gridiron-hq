## Method, so each column can be re-derived

- **merge-tree vs 654ff93**: `git merge-tree --write-tree origin/main <head>`. Exit
  0 = clean; otherwise the conflicted files are listed. This is content, not the
  base pointer GitHub shows — several PRs still record base `791b131`, which is
  stale but not itself a conflict.
- **shipped check**: #63/#52/#49 landed by *squash*, so their branch commits are
  not ancestors of main even though the content is in. Verified by marker rather
  than ancestry: `LIVENESS_PATH` (#56), boot `offThread` (#59),
  `reapAbandonedRuns` (#61), `NFL_SEASON="2026"` (#52), `grace_period="300s"`
  (#49) are all present in `654ff93`.
- **stacked**: base is another PR's branch, not main; the row names it. "vs-main
  conflict" for a stacked PR is what happens if it were retargeted to main as-is.
- **5Q**: does the body carry the five-question block (`Is it well built?` …).
  Mechanical scan of the body text.
- **check→commit**: `yes` = a commit sha sits on the body's check line;
  `figure, no sha` = a suite figure with no commit anchor; `no-figure` = no suite
  figure. Mechanical scan, and it can read a *reproduction* commit as an anchor
  when the suite figure itself has none — #48 was exactly that and is corrected
  below. The owning thread's own reading is authoritative per figure.
