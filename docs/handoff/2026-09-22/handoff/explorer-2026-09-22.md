## RULES AND LESSONS — what a new session must know

These are the ones I got wrong first and paid for. Each is a rule now.

1. **Licence before measurement. Always.** Unauthenticated and free to fetch is *not*
   permission to use. I measured Sharp Football before checking, which was the wrong
   order. And check properly: probe `LICENSE` and `LICENSE.md` across `master`, `main`
   *and* `gh-pages` — nflverse's lives at `master/LICENSE.md`, and my first Sharp check
   only looked at `main`, which was a hole. Sharp came back 404 on all six; the refusal
   stands on two independent legs. Nothing paid, ever; a free key may be requested from
   Nick, a subscription is logged as missing data.
2. **Name the tree.** A `file:line` without a sha is a guess. Quoting the Planner's
   numbers on `4a8085c`: the writer is `:563` not `:539`, the block `:447-559` not
   `:440-545`, there are **91** suffixes not 88, **six** single-consumer columns not
   five, and `drop_` is uncountable by grep. Memory: `gridiron-name-the-tree-rule`.
3. **Name the table, never the concept — and name the writer function with `file:line`**
   (fleet rule R54.5). I conflated `nfl_snaps` with `player_week_snaps` and wrongly
   reported role detection as exposed; `role-changepoint.js:49` reads
   `player_week_snaps`, which **is** scheduled. Memory: `gridiron-name-the-table-rule`.
4. **Two-copy production read (R49).** Any "0 rows" or "table absent" claim made
   *through* an import is ambiguous, because the import creates schema. Census the
   pristine snapshot before importing anything. The premise I originally supplied for
   this was itself wrong and I corrected it by measuring: `server/db/index.js:184-186`
   applies only `000_legacy_schema` at import — which created **215 tables** with
   exactly **1** row in `schema_migrations`. The correction made R49 stronger, not
   weaker.
5. **My `entity_season` "defect" was an artefact of my own rig, and I retracted it.**
   `syncInjuries` failed writing `nfl_feature_revisions` because migration `050` was
   never recorded in my rig. Before routing a defect, check whether your harness built
   the condition.
6. **No magnitude carries between rigs.** My rebuilt rig grades n=4,361 player-weeks;
   the historical figure was n=4,343. Same shape, different population. Directions
   carry; numbers do not. Never quote a number measured on one rig as if it were
   measured on another.
7. **A failing test is never "a flake" until proven, and "no API key" is not a cause.**
   (CLAUDE.md, and this project lost weeks to exactly that.) Same discipline for a
   zero or an empty result from a bespoke check: get one known-nonzero case through the
   same code path first, or the zero means nothing (the contradiction test).
8. **Test the fixture, not just the happy path.** I crashed twice on made-up schemas —
   a fake `nfl_snaps` whose column list did not match made the migration throw, and a
   wrong-quoted INSERT silently wrote 0 rows. Use real schemas and check the row count
   you think you wrote.
9. **Read a `git log -L` result against a control.** I wrote "file untouched" from an
   empty `-L` result; `git log --oneline -- <file>` showed `f620a12` had touched the
   file, just not the gate lines.
10. **Secrets: presence only, never content.** Environment variables only, never in the
    repo, a commit, chat or a screenshot.
11. **2025 is the protected holdout.** Never fetched, never run on. The rig seeds
    2022–2024 only.
12. **One editor per server file.** `projections.js` → Model evidence audit;
    `weekly-ensemble.js` → Fantasy plan; `ceiling-lineup.js` → UI. New scratch files
    are fine; edits to existing repo files are the coordinator's routing call.
13. **No pushing, no PRs, no merges, no deploys, no settings or secret changes without
