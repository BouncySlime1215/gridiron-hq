**UNIT 1 VERDICT (early-week blend) — ACCEPT design, ACCEPT running in production, one condition.** Full record /mnt/project-files/audit-unit-1-early-week-blend-2026-09-22.md. Key points:
- Statistics hold: pre-registered gate 2026-09-18 before grading, walk-forward, paired bootstrap clustered on player_id (seed 20260918, 2000 iters), baseline pinned by fit id. Winner was the SIMPLEST arm (structural-only) — not the shape p-hacking takes.
- Measured cost of current blend, weeks 2-4: MAE 4.7233 vs 4.4867 (2024, n=929), 4.7099 vs 4.3175 (2025, n=969), 90% CIs exclude 0. Start/sit 0.605→0.626, 0.621→0.647. **These are the evidence — the "22.40-point swing" is an illustration, do NOT quote it as measurement.**
- **CORRECTION OF THE CORRECTION, 2026-09-22 12:15Z — the "60/50/40/20" figure was WRONG and this supersedes it wherever it appears.** Read off `weekly-ensemble.js:56-63`: heads are `[structural, season_to_date, last3, last1, median]` and the frozen fallback is QB `[0.40,0.45,0.00,0.10,0.05]`, RB `[0.50,0.20,0.10,0.15,0.05]`, WR `[0.60,0.00,0.00,0.10,0.30]`, TE `[0.80,0.20,0.00,0.00,0.00]`. So **structural-head exposure is QB 40 / RB 50 / WR 60 / TE 80** — QB and WR were transposed and TE's 0.80 was written as 20. **CORRECTION OF THAT CORRECTION, 12:32Z: the SEQUENCE 60/50/40/20 QB/RB/WR/TE is exactly the HISTORY-head exposure (1 - structural: 0.45+0.10+0.05=0.60, 0.20+0.10+0.15+0.05=0.50, 0.10+0.30=0.40, 0.20=0.20). The error was only ever the LABEL. Withdraw it as a structural reading; it is correct as the history share, and a blanket withdrawal deletes a true statement.** Still per-position, still NOT 80% uniform; `[0.20,0.40,0.15,0.05,0.20]` is fit-1, not the fallback. Material because per [[gridiron-live-read-2026-09-22]] this fallback is what production actually serves. (Nick was given the 60/50/40/20 form at 07:23Z; it needs correcting to him.)
- **CORRECTION: "promotion into the wrong epoch serves nothing" cannot happen** — write and read call the same epoch fn in-process, round trip demotes on mismatch. Real risk is the mirror image (epoch rollover AFTER promotion → silent frozen-2023 fallback), the Scheduler's unit.
- **Operational gotcha for whoever runs the script:** data_hash is stored prefixed `e{epochId}:` with `ON CONFLICT(data_hash) DO NOTHING`. Re-run in same epoch with identical inputs inserts nothing and still prints OK — read `report.saved.inserted`, "exit 0" doesn't prove a write. If that hash was ever promoted then demoted, it exits 1 forever until the hash changes or the row is cleared.
- **Still unproven (the condition): has the script EVER run against production.** Gate-1 criteria for the live read, all three required: (a) active epoch id from `nfl_learning_epochs WHERE status='active' ORDER BY id DESC LIMIT 1`, stated not assumed; (b) every `weekly_ensemble_fits` row with promoted=1 AND that epoch_id (id, data_hash, through_season, through_week); (c) for the top row, whether weights_json has an `early` key + its weeks window and bucket keys. Two of three = still exposed and looks fine from outside.
- Standing: bucket 3 (EARLY_WEEK_MAX_PRIOR_WEEKS=3) ships a behaviour change whose own CIs straddle 0 — never describe bucket 3 as evidence-backed.
