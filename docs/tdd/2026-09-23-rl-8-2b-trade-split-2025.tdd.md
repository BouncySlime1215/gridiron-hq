## 4. What it does

`scripts/rnd/trade_split_2025.py` makes one run with three stop-controls, then grades the two arms.
- **C1**: the same code path, run on 2021-24, reproduces r8: n = 210, 0.576 [0.515, 0.633]. Otherwise it stops.
- **C2**: linkage to `trade_sides` / `sides_ext`, and the team_weeks started-points check (>= 95%).
- **C3**: the roster-spot charge fires, and the lineup-value pick differs from the summed-consensus pick on some
  trades.
- `lineup_value(roster, gives, gets, rate, pos, points, wire)` mirrors PR #200. It holds roster size. A freed spot
  is filled from the wire: the best free agent at each position, then whichever raises the lineup most. A needed
  spot drops the least-missed player. `per_week` is the change in the best lineup. Player rate is the consensus
  value, so arm (b) asks one thing: on the same player values, does lineup-and-roster-spot aggregation beat simple
  summing?
- `--smoke` runs every step but prints counts only. It exists so the pipeline and the call-site mutants could be
  checked on 2024 without reading any outcome.

Reading, in plain words:
- **(a)** In 1-for-1 trades where the consensus pick and the season-to-date pick point different ways, following
  consensus is a coin flip (0.505) in lineup points. The test could have detected an edge of about 13 points
  (MDE80 0.128). An edge of 5 points (0.55) would have been missed often, so this is "no edge large enough to
  detect", not proof of zero. The random-player placebo scores higher (0.607, n = 28), which also argues against a
  consensus-specific edge over humans. Across all 1-for-1 trades, consensus does pick the winner more often than
  not (0.570). It fails only where it disagrees with the box score, and that is the only place it would change a
  decision.
- **(b)** The lineup-value model cleared its own two bars (0.551 > 0.55; lower bound 0.504 > 0.50). The rule also
  required summed consensus to fail on the same trades (<= 0.50), and it did not (0.517). So this does not show
  that lineup value rescues a case where consensus fails. The head-to-head gap (0.551 vs 0.517, +3.4 points) is
  smaller than the MDE (about 7 points), and a difference test was not pre-registered. It is a direction, not a
  finding.
- **Post hoc, cannot decide anything:** the model looks better on 2-for-1 (0.591) than on 2-for-2 (0.485). This
  split was noticed after the run. It needs its own fresh test (2026 forward). 2025 is now spent for this question.

## 8. Known defects and limits

  (`select season,count(*) from nfl_ffopportunity_weekly ...`, `mode=ro`) was run against
  `~/gridiron-local/data.sqlite` directly. No write. Every study read used the copy.
- Historical stand-ins for PR #200's inputs:
  - Player rate is the consensus value (ECR curve), not the product's `adj_ppg`.
  - Byes are not modelled (constant ROS rates, so `lineupSpan` reduces to per-week).
  - The pre-trade roster is rebuilt from the `w0` roster, so a pickup made between the trade and `w0` sits on both
    rosters.
  - The wire is board players unrostered at `w0`.
- `y_L` counts only traded players' starts, so a freed spot's pickup is invisible to the primary outcome. S1
  (`L_rule`, whole roster) counts it and points the same way (0.559).

  have not recounted it either; the STATS-METHOD rule 3 command recounts it.
