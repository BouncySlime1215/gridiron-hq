# EA-07: one world per NFL week

Unit EA-07 (ENGINE-ARCHITECTURE §4.7, §10.2 rows A-C; BROKEN-NUMBERS rows A, B, C).
Branch `claude/cloud-ea-07`, cut from PR #241's head `d748c02` (RL-17-3, folded:
the one world always reads `proj.ros`). Flag `GRIDIRON_ONE_WORLD`: `1` on, `0` off,
unset = on only under `GRIDIRON_PREVIEW_UNCONFIRMED=1` (preview-mode.js), labelled.

## 1. Audit: extend or build

- **Row B (three title odds for one team).** Three caches, three keys, and a fresh
  world per call: `/simulate` (routes/model.js memo, random seed unless `?seed`),
  `titleOddsTrades` (its own `tradeImpactWorld` per `fetched_at`), `tradeImpact`
  (per-sync seed, uncached), plus `myPlayoffOdds` (its own seed and 1,000 runs).
- **Row C (four weekly ranges for one player-week).** trade-engine.js asset
  floor/ceiling (`playerWeekDistribution`, seed hashed from a cache key, in-season
  weekly engine), season-sim.js pools (per-call world), ceiling-lineup.js (unkeyed
  pools on another projection build, PPR, availability 1), lineup-posture.js
  (positional-CV normal).
- **Extend, not build.** RL-19-2's `tradeImpactWorld` already is a world built once
  with every player-week's pool and every run's draws; RL-17-3 already centres it on
  `ros_ppg`. What was missing: a world named by the NFL week, held once per league
  snapshot, and every reader pointed at it. The engine spine (#216, EA-00) is not on
  main, so there is no `engine_state` row to write: the world is process memory
  (as RL-19-2's is), and no migration is needed.

## 2. Change

- `one-world.js` (pure): the flag, `oneWorldSeed(season, nflWeek) =
  keyedSeed('world', season, week)`, RL-17-3's `rosFactor`, and `rangeFromPool`
  (quantiles at `floor(q x n)`, the index the copula maps u = q to).
- `season-sim.js`: the pool draw is one function (`weekPool`), used by
  `prepareSeason` and exported as `worldPoolFor` for the one caller the world is
  built on (the asset universe). `prepareSeason` takes a named `worldId` (no stream
  draw); with the flag on `tradeImpactSeed` is the week's world and
  `tradeImpactWorld`/the old two-run path use it as the world id. The world key gains
  `mode` so a stream world is never reused as a week world. `rosBasisFlag` is on
  whenever the one world is (an explicit `GRIDIRON_RL17_3_ENABLED=0` still vetoes).
  Pools are kept on `weekData.pools`. Off: byte-identical (RL-17-3, RL-19-2, RL-6-3
  suites unchanged).
- `league-world.js`: `leagueWorld(lg)` built once per snapshot key (league,
  `fetched_at`, season, NFL week, start week, scoring, basis, runs =
  `TRADE_IMPACT_RUNS` 1,200); `oneWorldTitleOdds`, `worldRange`, `worldPool`,
  `worldStamp` (`snapshot_id`, `world_id`, ...). Cleared with `clearModelCache`.
- Readers, flag on: `/simulate` serves `oneWorldTitleOdds` (runs/seed/from_week
  echoed as `ignored`); `/trade-impact`, the Title tab and the sense-check price on
  `leagueWorld(lg)`; `myPlayoffOdds` reads the world's playoff odds; the asset
  universe's floor/ceiling/avg/boom/bust and the lineup-spread moments come from
  `worldPoolFor` (`range_source: 'world'`); the ceiling lineup uses the world pools
  with the world's copula keys and run-indexed draws; the posture's per-player SD is
  the world pool's SD.
