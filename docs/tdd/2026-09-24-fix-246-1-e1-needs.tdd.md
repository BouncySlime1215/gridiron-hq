## Why

On the coordinator's DB copy (9/24), E1 graded n = 37 league offers: gain -0.0043 nats,
95% CS -0.68 to +0.68. The report said **"needs 171590 more offers"**. The old projection
asked the CS to shrink until its full width was 2 x max(|gain|, 0.01) = 0.02, starting
from 1.36: (1.36 / 0.02)^2 x 37 total. A gain near zero made the target near zero,
and the count exploded.

## What changed

| before | after |
|---|---|
| target full width = 2 x max(\|gain\|, MIN_GAIN = 0.01) | target half-width = max(\|gain\|, current half-width / 2) |
| width scaled as 1/sqrt(n) (fixed-n formula) | width scaled as sqrt(log(n) / n), the betting CS's rate (`sequential.js#projectedTotalN`) |
| no cap | capped at 10 x n; past it: `needs more than N more offers (effect near zero)` |
| excluded offers: totals only | `detail.offers_by_league = { league_id: { gradable, accepted, excluded } }` (`mergeOffers` now returns `excluded_by_league`) |
| - | `detail.needs_projection = { target_half_width, half_width, capped, cap_x }` |

Real-DB shape: 171,590 -> **183** more offers (`needs 183 more offers`), not capped.
