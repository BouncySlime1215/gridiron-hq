# M7-TIMING: urgency windows -> send_when on campaign steps (2026-09-24)

PEOPLE-WIRING.md module 7 ("send when his urgency spikes: injury, losing streak, 'need a
move'"). Stacked on PR #233 (CAMPAIGN-01 producer, head `6429dc23`): the campaign steps and
their `send_when` field only exist there.

## 0. Audit (the row's cause)

- `scripts/campaign/league-adapter.mjs:187` (at `6429dc23`) set every manager's
  `send_when` from `trade-tactics.js:373#sendWindow` alone. That function has one way to
  say "wait" (a decline inside 48 hours) and no urgency input at all, so no step could say
  "send now, his window is open" or "wait N days, the crunch lands next week".
- `server/services/campaign/view.js:83` (at `6429dc23`) printed a wait as `after <until>`,
  with no day count.
- No 'need a move' label exists anywhere in the repo or the chat DB aggregates; the chat
  reader (`scripts/campaign/chat-labels.mjs`) read profile aggregates only.
- PR #252 (CAMPAIGN-PEOPLE) has a `timing()` that reads `urgency_windows` off the chat
  profile; nothing computes those windows. This unit computes them from observable state and
  does not depend on #252.
- Decision: **build** `server/services/campaign/urgency.js` (pure) and wire it through the
  adapter; edit the view's sentence; no migration.
