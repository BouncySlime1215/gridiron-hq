# E-BAYES — pre-registration (2026-09-25)

Scope: Batch D plan item 6 ("E-BAYES (P2, shadow only): pooled hierarchical acceptance model (per
manager, partial pooling across 5 leagues), plain JS, graded forward on first-seen predictions. It
never drives served P(yes) until it passes its pre-registered bar."), and ONE-PLAN night 3
("P(yes) = pooled Bayesian activity prior per manager"). This record is written before the code.

## What changes

- New shadow model `server/services/eval/e-bayes.js`: a three-level beta-binomial on decided offers.
  - global accept rate mu_g = (acc + 1) / (n + 2) over every league;
  - each league's rate mu_l ~ Beta(kappa_L mu_g, kappa_L (1 - mu_g));
  - each manager's (league, roster id) rate ~ Beta(kappa_M mu_l, kappa_M (1 - mu_l)).
  - kappa_L and kappa_M are fitted by empirical Bayes (maximum beta-binomial marginal likelihood on a
    fixed log grid 0.5..500) from the answers known before the cutoff. With fewer than two groups at
    a level the kappa falls back to a fixed default (league 20, manager 5 = E1's SHRINK_K).
  - Prediction for a manager = posterior mean (acc + kappa_M mu_l) / (n + kappa_M). An unseen manager
    gets mu_l; an unseen league gets mu_g. Content of the offer is not read (same as the baseline).
- As of any time t it uses only offers RESOLVED strictly before t (`eval/e1-league.js` cutoff), so a
  prediction replayed at an offer's proposal time is exactly the prediction it would have made at
  first sight.
- Forward grader `gradeForward(offers)` over the E1 decided-offer set (`decidedOffers` via
  `loadLeagueOffers`, one producer), in proposal order.
- Flag `GRIDIRON_EBAYES_SHADOW=1` (its own flag; not `GRIDIRON_PREVIEW_UNCONFIRMED`): `pYesTableFrom`
  attaches a `shadow_e_bayes` table (per-team p, n, level). Nothing reads it for a served number:
  `pYesFor`, `stepPYes`, `pYesBasis` and plans.json are byte-identical with the flag on or off.
- `scripts/e-bayes-grade.mjs`: prints the forward grade from the local database (Mac only).

## Metric and bar (pre-registered)

**Metric.** Forward log loss per settled offer (all 5 leagues), each offer scored by
(a) E-BAYES fitted on answers known before its proposal, and (b) the SERVED blend with the weights
as they stood at its proposal (`p-yes-blend.js#blendState` at `proposed_at`, baseline and clone as-of
predictions from `scoreAsOf`/`activityBaseline`). p clipped to [0.02, 0.98] (E1's clip).
gain_i = loss_blend_i - loss_ebayes_i (> 0: E-BAYES better). 95% anytime-valid confidence sequence
(`eval/sequential.js#confidenceSequence`, range +-log(49)). Also reported, not judged: gain vs the
activity baseline.

- **PASS** (eligible to be proposed as a served arm, in a separate PR Nick approves): n >= E1's
  `minOffersToDecide()`, CS lower bound > 0, and mean gain >= 0.01 (E1 MIN_GAIN).
- **FAIL**: CS upper bound < 0 (E-BAYES is worse than the served blend at any n). It stays shadow,
  and the result is reported.
- Otherwise **NOT DECIDED**: stays shadow; reported with n and the CS.

## What would fail it (tests)

1. Any served field (`pYesFor` output, `stepPYes`, `pYesBasis`) differs with the flag on vs off.
2. A prediction that reads an answer resolved at or after the cutoff (future leak).
3. Posterior mean not equal to the hand-computed beta-binomial value for a small fixture.
4. No partial pooling: a manager with 0 of 1 accepted is pulled to 0 or left at the league rate.
5. An unseen manager not getting its league rate, or an unseen league not getting the global rate.
6. The fitted kappa not tracking the data (heterogeneous managers must fit a smaller kappa_M than
   identical ones).
7. `gradeForward` returning PASS below `minOffersToDecide()` offers, or a verdict disagreeing with
   the CS rule above.
