# E-DATA — pre-registration (2026-09-25)

Scope: Batch D item 2 (Nick, 2026-09-25): (a) capture every ESPN trade offer the moment it
appears and pair each answer with its proposal, under 10% orphans, polling faster in active
hours; (b) at first sight of each offer, record every model's P(yes) (baseline, clone, blend)
so LIVE-BLEND's weights can be earned forward on the served model; (c) a FantasyCalc value
history table, time-stamped, not latest-only. This record is written before the code.

Builds on, does not copy:
- the pairing: `eval/decided-offers.js#rawOfferGroups` (#409 LEDGER-BACKFILL, E1's one producer).
  It already reads `trade_proposal_snapshots` when the table exists; this unit builds that table.
- #247 OFFER-SNAPSHOT's design (first write wins, terms kept before the raw upsert overwrites
  them), without its second pairing table (`trade_outcome_links`): orphans are counted by
  decided-offers.js, which is the one producer of that count.
- LIVE-BLEND (`p-yes-blend.js`), PYES-ONE (`p-yes.js`), `fc-value.js` (the one FantasyCalc reader).

## What changes

- Migration 106: `trade_proposal_snapshots`, `offer_first_sight`, `fc_value_history` (additive).
- `server/services/offer-capture.js`: snapshot writer, first-sight recorder, orphan report,
  poll cadence.
- `scripts/collect-league-transactions.mjs`: writes both tables in the same pass as the raw rows.
- `scripts/watch-trade-offers.mjs`: the fast poller (all ESPN leagues), started by the refresh
  loop only with `GRIDIRON_OFFER_WATCH=1`. 120 s between 07:00 and 24:00 America/New_York,
  600 s otherwise (env-tunable).
- `p-yes-blend.js#forwardGraded`: LIVE-BLEND weights from first-sight predictions only. Served
  only with `GRIDIRON_PYES_FORWARD=1` (off by default: plans.json byte-identical with it off).
- `routes/aggregates.js#syncFantasyCalc` appends every capture to `fc_value_history`;
  `fc-value.js#fcValuesAsOf` reads the value in force at any instant, same fail-closed shape.

## Metrics and bars

1. **Orphan rate (needs local measurement).** orphans / (decided + orphans), per league and
   pooled, over answers first collected after the watcher started (`offerCaptureReport`).
   PASS: pooled < 10% and every league with >= 10 answers < 10%, after 7 days of the watcher.
   FAIL: pooled >= 10%. Baseline (brief, #247): 38 of 82 decided offers had no proposal row.
2. **Capture (tests).** An offer seen pending once, then resolved with `items: []`, keeps its
   terms; an offer whose raw proposal row is gone still pairs with its answer through the
   snapshot (E1 counts it as decided, not `missing_proposal`). Re-capture never rewrites.
3. **Cadence (tests).** 120 s at 07:00 and 23:59 ET, 600 s at 03:00 ET; env overrides work;
   the refresh loop starts the watcher only with the flag and never with GRIDIRON_PREVIEW_UNCONFIRMED.
4. **First sight (tests).** Every offer first seen from a live ESPN response gets exactly one
   row with p_baseline, p_clone, p_blend and p_served (or a typed reason); a second sighting
   never rewrites it; the offer being predicted and answers collected after first sight never
   enter its own prediction; rows backfilled from old raw rows get no prediction.
5. **Forward weights (tests).** `forwardGraded` uses only rows seen while pending, in answer
   order, with the recorded p's; with the flag off the served P(yes) is identical.
6. **FantasyCalc history (tests).** Two syncs on one day give two rows per player and source;
   `fcValuesAsOf(t)` returns the value in force at t, `table_absent`/`empty` otherwise;
   `fcValues` (what Nick's rules read) is unchanged.

## What would fail it

A served number that moves with the flags off; a first-sight row rewritten or leaking its own
answer; an offer E1 counts as decided losing its pairing; the Mac orphan rate >= 10% after a
week of the watcher.
