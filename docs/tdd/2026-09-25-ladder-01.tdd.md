# LADDER-01: ladder cards (shadow)

ONE-PLAN section 5, night 5: "chained finish may spend the acquired piece with the mode's max give;
backup branch at each 'no'; Fuck-it ladders capped at 2 steps while p is the 0.30 guess (floor
0.03)". Deliverable: "ladder cards depth -> level-below -> blue chip with P(yes) per step and the
backup". Acceptance there: "0 final-leg gets below the floor".

Flag: `GRIDIRON_LADDER=1`. Default off, and preview does NOT turn it on. Off, the planner never
calls the module and the producer's entry is byte for byte today's.

## Pre-registration (written before the GREEN code)

- Metric 1: final gets under Blue chip 83 on ladder cards. Pass bar: 0.
- Metric 2: rungs that give 160 / 80 / 277 or an `adapter.untouchable` id, or get 290. Pass bar: 0.
- Metric 3: rungs that give more market value than they get past the cap. Pass bar: 0.
- Metric 4: Fuck-it cards longer than 2 rungs while any rung's p is the guess. Pass bar: 0.
- Metric 5: every rung carries p labelled `guess: true` and an `on_no` (backup or stop). Pass bar: 100%.
- Metric 6 (shadow): with the flag on, every section of the entry other than `ladders` equals
  the flag-off entry (deep-equal), in all three modes. Pass bar: identical.
- Fails it: any single violation above, or the flag-on entry failing `validateLeague`.

## What changed

- `server/services/campaign/ladder.js` (new, pure): `ladderFlag`, `tierOf`, `scoreReader`
  (`adapter.scoreOf`, else the PLAYER-SCORE board rows, else none: fail closed), `ladderCards`
  (filters above, each counted in `dropped_by_reason`; backup at each "no" is the best other
  kept ladder sharing the rungs before it, else "stop" with what the earlier rungs landed), and
  `ladderSection` (the typed plans-file section; every number `guess: true`).
- `planner.js`: with the flag on, `ladderCards(ranked, ...)` after the mode ranking; result gains
  `ladders`. Nothing else reads it.
- `view.js`: `ladders` section written only when `res.ladders` exists.
- `plans-schema.js`: optional section `ladders`, `LADDER_TIERS`.
- The search is NOT changed. `stepsFrom` already reads the chained state's roster, so a chained
  finish can spend the acquired piece today (test 3 proves it). Widening that finish to the
  mode's max give is REACH-01's `chainGive` (#378); this unit reads whatever the search returns,
  so it composes with #378 without touching the same lines.
