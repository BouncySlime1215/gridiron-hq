## Pre-registration (written before the fix)
- Metric: of the 64 cells (report status Out/Doubtful/Questionable/none x practice
  DNP/limited/full/none x QB/RB/WR/TE), how many does serving classify as out/not-out

- What fails it: any cell classified differently; any served evidence that still prints a
  P(out) number (the role layer is that number's one producer); `FITTED_EFFECTS` changing

## Cause
`buildRadarRows` defaulted to `loadPOut()` (the role-layer table, fitted 2021-24), while the fit
script passed `fitPOut(2021-23)`. The effects were fitted with one definition of "out" and served
with another.

## Rebase note: why-now label with the radar present but off
Main's RADAR-WIRE (`why-now.js`) treats any adapter with an `opportunityOf` function as radar
'on'. Rebasing #377 as it was would have made every flag-off flip row read "No why-now signal"
instead of saying the radar is off. The adapter now exposes `opportunityOf` only while
`GRIDIRON_OPP_RADAR=1`, else `opportunityRadar: 'off'`, and why-now prints "O1 radar off."
(`off` was already in the plans schema).
